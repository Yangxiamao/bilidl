# 字幕：B 站能给什么，给不了时怎么办

## B 站的字幕接口（2026-10 实测）

- **接口**：`/x/player/wbi/v2?bvid=..&cid=..`，需要 WBI 签名（`wts` + `w_rid`，密钥来自 nav 接口里两张图片的文件名）。返回 `data.subtitle.subtitles`，每条有 `lan`、`lan_doc`、`subtitle_url`（`//` 开头，带 `auth_key`，几小时后过期，所以要现取现下）、`ai_type`、`ai_status`。
- **不签名的 `/x/player/v2` 不可靠**：同一个视频连续请求 4 次，有 1 次返回的是一条 `ai-zh` 字幕，内容来自别的视频（213 秒的视频，字幕最后一句在 689 秒）。签名的 `wbi/v2` 连续请求多次结果一致。保险起见，下载时如果字幕结束时间比视频时长多出 30 秒以上，会当成串台跳过。
- **必须登录**：游客身份请求，`subtitles` 永远是空列表，人工字幕和 AI 字幕都拿不到。「没有字幕」最常见的原因其实是没登录。
- **字幕的种类**：
  - 人工字幕：`lan` 是 `zh-CN`、`en-US`、`ja` 这样的代码，由 UP 主或字幕志愿者上传。
  - AI 字幕：`lan` 以 `ai-` 开头。`ai_type=0` 是对原声做语音识别（通常是 `ai-zh`），`ai_type=1` 是从识别结果机器翻译出来的（`ai-en`、`ai-ja`、`ai-es` 等）。
- **字幕格式**：JSON，`body` 是 `[{from, to, content}]`，秒为单位。bilidl 转成 SRT（UTF-8 带 BOM），存成 `<视频名>.<语言>.srt`，播放器会自动加载。

### 覆盖率

2026-10-15 抽了热门榜前 30 个视频（已登录）：

| 情况 | 数量 |
|---|---|
| 有人工字幕 | 1 |
| 只有 AI 字幕 | 20 |
| 什么字幕都没有 | 9 |

也就是说，登录后大约 70% 的视频能拿到字幕，但几乎都是 AI 识别的。AI 字幕的质量一般够看，但有典型的识别错误，例如「一窍不通」被识别成「AI1窍不通」。没有字幕的 9 个里，有 15 秒、46 秒的剪辑，也有 10~20 分钟的 vlog、美食、美妆视频，后者都有大段人声，按理说能识别，只是 B 站没有生成。

## B 站不提供字幕时的替代方案

按「先排除假阴性，再自己生成」的顺序：

### 0. 先确认是真的没有

- **登录**：没登录时接口一律返回空列表。bilidl 在这种情况下会提示「未登录时 B 站不返回字幕」。
- **分P**：字幕按分P（cid）分别提供，同一个视频可能只有部分分P有字幕。
- **画面里已经有字幕（硬字幕）**：很多 UP 主用剪映等工具自动生成字幕后直接压进画面，所以 B 站上没有单独的字幕轨。看视频不受影响，只有想要文字稿时才需要下面的方案。

### 1. 本地语音识别（推荐）

先下载音频流（bilidl 本来就会单独下音频，每分钟约 1 MB），再交给本地 ASR 模型，输出带时间轴的 SRT。

| 方案 | 适合 | 优点 | 缺点 |
|---|---|---|---|
| **faster-whisper**（Whisper large-v3 / large-v3-turbo，CTranslate2 推理） | 多语言、外语视频 | 识别 99 种语言；有 GPU 时速度远快于实时；pip 就能装 | 模型 1.5~3 GB；中文输出常常没有标点，有时简繁混杂；纯音乐、静音段会「幻觉」出不存在的句子，必须开 VAD（它自带 `vad_filter`） |
| **FunASR：Paraformer / SenseVoice-Small**（阿里达摩院） | 中文视频 | 中文准确率高，自带标点和时间戳；SenseVoice-Small 在 CPU 上也很快 | 依赖 PyTorch，安装体积大；外语能力不如 Whisper |
| **whisper.cpp** | 不想装 Python 依赖 | 单个可执行文件，CPU/GPU 都能跑，可直接输出 SRT | 要单独下载程序和模型；和 bilidl 的集成只能走子进程 |

本机（RTX 4060 Laptop、32 GB 内存）跑这几种都没有压力。

### 2. 云端语音识别 API

阿里云、腾讯云、讯飞、火山引擎（和剪映同属字节跳动）都有「录音文件识别」，中文效果好，可以直接输出带时间戳的句子；OpenAI 的转写接口适合外语。

- 优点：不占本机资源，不用下载模型，中文准确率通常比开源模型高。
- 缺点：按时长收费；需要注册并保存 API key；要把音频上传到第三方，对隐私敏感的内容不合适。

### 3. 硬字幕 OCR

画面里已经压了字幕时，直接识别画面文字往往比重新做语音识别更准（UP 主多半校对过）。常见做法是：用 ffmpeg 按固定间隔截取画面底部的字幕区域 → 用 PaddleOCR 识别 → 合并相邻的相同文本得到时间轴。也有现成的工具，例如 VideoSubFinder（提取字幕帧）配合 OCR。

缺点：字幕位置和样式因视频而异，需要调裁剪区域；画面里有其他文字时会误识别；时间轴精度取决于截帧间隔。

### 4. 弹幕（不是字幕，但有时能用）

bilidl 可以用 `--danmaku` 把弹幕转成 ASS 字幕，用播放器叠加显示（见 [DANMAKU.md](DANMAKU.md)）。弹幕不是对白文字稿，但有少数视频由「字幕君」用弹幕打了字幕。

## 对 bilidl 的建议

- **已经做了**：从 B 站拿人工和 AI 字幕；未登录、没有字幕、只有不符合条件的字幕时，给出明确的原因。
- **下一步最值得做**：本地语音识别，作为可选功能：
  - 核心模块继续只用标准库；只有装了 `faster-whisper`（或 FunASR）才显示「生成字幕」选项。
  - 只在 B 站没有字幕时才运行，并且只下载音频流，不必下载视频。
  - 输出文件名用 `<视频名>.asr-<语言>.srt`，和 B 站的字幕区分开。
  - 识别很吃 CPU/GPU，应该放到单独的队列里，不要阻塞下载队列。
  - 中文视频优先用 SenseVoice/Paraformer，外语用 Whisper；Whisper 一定要开 VAD。
- 云端 API 和 OCR 适用面较窄，用户确实需要时再做。
